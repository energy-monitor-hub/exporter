# Оновлення експортера

[English](../UPDATES.md) · **Українська**

> Це переклад. Основна версія англійська ([docs/UPDATES.md](../UPDATES.md)); якщо тексти розходяться, правильна англійська.

Нові моделі й виправлення декодера приходять як підписані пакети декодерів
([DECODER_PACKS.md](DECODER_PACKS.md)), без нового образу. Ця сторінка про решту: нові версії
самого експортера.

## Що робить експортер

Він **повідомляє** про нову версію, але ніколи не замінює себе сам. Щоб замінити контейнер
зсередини, потрібен сокет Docker, а це root на хості, тож експортер його ніколи не отримує.

- `EXPORTER_UPDATES=notify` (типово) або `off`; `EXPORTER_CHANNEL=stable` (типово) або `beta`;
  `EXPORTER_RELEASES_URL=https://<your-site>/releases/releases.json`. Без URL і довіреного ключа
  нічого не завантажується.
- Приблизно через хвилину після старту і далі щодня завантажує `releases.json` і підпис
  (Ed25519, ті самі ключі, що й для пакетів декодерів), відкидає прострочений або старіший список
  і порівнює версії. Запит не містить ідентифікаторів; хостинг бачить IP-адресу і час.
- Сторінка стану показує поточну версію, а коли є новіша, банер з образом, **закріпленим за
  digest**. Якщо поточну версію відкликано, банер червоний.

Як оновити:

```bash
make exporter-update                                   # тег :main, як і раніше
# або закріпити точний реліз з банера (deploy/.env чи shell):
ECOFLOW_EXPORTER_IMAGE=ghcr.io/<owner>/<repo>@sha256:<digest> make exporter-update
```

Digest ніколи не змінюється, тож закріплений експортер лишається точно таким, доки ти не зміниш рядок.

## Випуск релізу (мейнтейнер)

1. Збільш `version` у `package.json`, злий у `main`.
2. Постав на коміт злиття тег `vX.Y.Z` і запуш його. `exporter-image.yml` звіряє тег з
   `package.json`, збирає amd64 + arm64 з **SLSA build provenance**, пушить `exporter:vX.Y.Z`
   (релізні теги ніколи не прибираються) і виводить digest та готовий запис для `releases.json`
   у підсумку запуску.
3. Додай запис у `releases/releases.json` з `"channel": "beta"` (pull request). Деплой вебу
   підписує і публікує його разом з дашбордом.
4. **Карантин**: через 7 днів без повідомлень про проблеми зміни на `"stable"` (ті самі 7 днів, що й
   правило npm у `CLAUDE.md`). Лише тоді стабільні експортери його бачать.
5. Аварійний вимикач: `"revoked": true` для поганого релізу. Експортери на ньому показують червоний
   банер, і його більше ніколи не пропонують.

`min_db_migration` це найновіша міграція, потрібна релізу на сервері. Застосуй міграції до того,
як позначати реліз стабільним.

## Перевірити образ вручну

```bash
docker buildx imagetools inspect ghcr.io/<owner>/<repo>@sha256:<digest> \
  --format '{{ json .Provenance }}'
```

Provenance називає репозиторій, коміт і workflow, що зібрав образ. Порівняй digest з тим, що в
`releases.json` і в підсумку релізного запуску.

## Ще не зроблено

- **Оновлення без участі для Docker**: окремий сервіс-оновлювач із сокетом Docker, який приймає
  лише digest з перевіреного списку, з перевіркою здоров'я і автоматичним відкатом. Це справжній
  компроміс (доступ рівня root в одному контейнері), тож він лишається необов'язковим і ще не
  зроблений. Десктопний застосунок використовуватиме власний підписаний оновлювач платформи.
- Показ оновлення ще й на вебдашборді (зараз: сторінка стану і логи).
