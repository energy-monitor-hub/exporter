# Плагіни пристроїв

[English](../DEVICE_PLUGINS.md) · **Українська**

> Це переклад. Основна версія англійська ([docs/DEVICE_PLUGINS.md](../DEVICE_PLUGINS.md)); якщо тексти розходяться, правильна англійська.

Кожен тип пристрою, який уміє читати експортер, це один **плагін пристрою**: бренд і спосіб
до нього дістатися (хмарний MQTT, локальний Modbus TCP, Bluetooth, HTTP API). Усе, що
залежить від виробника, сховано за плагіном. Решта експортера (сторінка налаштувань,
зашифровані облікові дані, пакети декодерів, перепис моделей, черга і запис у Supabase)
працює лише через нього та через спільну модель, тому ніде не називає виробника.

Зараз є один плагін, `ecoflow-mqtt` (станції EcoFlow через акаунт застосунку EcoFlow).
Інші пристрої додаються лише тоді, коли є справжнє залізо для перевірки (issue #12).

## Як читається пристрій

```
DevicePlugin (src/sources/<plugin>.ts)
  ├─ setup: поля форми, тексти, змінні .env          → сторінка статусу будує форму
  ├─ credentials (схема zod), verify()               → сторінка налаштувань перевіряє і зберігає зашифрованими
  ├─ productCode()                                   → вибирає пакет декодера (vendor + код)
  └─ open() → Source                                 → підключається, віддає сирі повідомлення
                 ├─ adapter: DeviceAdapter            → спільна модель (src/model/types.ts)
                 └─ discovery: DiscoveryCodec         → перепис моделей, зразки за згодою
```

- **`DevicePlugin`** (`src/sources/types.ts`) описує тип пристрою. `id` вказує `SOURCE` у
  `.env`, і він же зберігається поруч з обліковими даними в зашифрованому файлі. `vendor`
  потрапляє в `devices.vendor` і вибирає пакети декодерів.
- **`Source`** це одне відкрите з'єднання з одним пристроєм: `start`, `stop`, `reconnect`,
  `onPayload` і ідентифікатори, які треба маскувати у зразках. Протоколи з опитуванням
  (Modbus, HTTP) опитують усередині source і віддають прочитане як повідомлення.
- **`DeviceAdapter`** (`src/model/types.ts`) перетворює повідомлення на `TelemetrySample`,
  `PackSample` і `DeviceState`. Плагін має вбудований адаптер; підписаний пакет декодера
  ([DECODER_PACKS.md](DECODER_PACKS.md)) може замінити його без релізу.
- **`DiscoveryCodec`** (необов'язковий) підказує перепису моделей, які типи повідомлень є в
  payload і як маскувати в ньому ідентифікатори. Без нього перепис і зразки для цього
  плагіна вимкнені.

## Інтерфейс плагіна

```ts
interface DevicePlugin<C extends { sn: string }> {
  id: string;            // 'ecoflow-mqtt'; SOURCE, зберігається з обліковими даними
  vendor: string;        // 'ecoflow'; devices.vendor, пакети декодерів, перепис
  setup: { title; hint; privacy; fields: FormField[]; envVars: string[] }; // тексти en + uk
  credentials: ZodType<C>;
  fromEnv(env): C | undefined;            // усі змінні задані, або undefined
  verify(c: C, log): Promise<void>;       // кидає помилку, якщо пристрій або його хмара їх не приймає
  productCode(c: C): string;              // код сімейства моделей ще до підключення
  open(c: C, ctx: { config, logger, adapter? }): Source;
  describeFatal?(err): string | undefined; // зрозумілий рядок для відхиленого входу
}
```

Облікові дані завжди містять серійний номер пристрою (`sn`): він визначає пристрій у
`public.devices` (через `ensure_device`) і маскується всюди, де може залишити машину.

## Як додати плагін

1. Напиши `src/sources/<id>.ts` з плагіном (`definePlugin({...})`), його `Source` і вбудованим
   `DeviceAdapter` (у `src/decode/`). Транспорт тримай в окремому модулі, як `src/mqtt/` для
   EcoFlow.
2. Додай його в `PLUGINS` у `src/sources/index.ts`. Більше нічого в експортері міняти не треба.
3. Тести працюють на записаних фікстурах із замаскованими ідентифікаторами
   (`src/record/scrub.ts`), ніколи на живому пристрої в CI.
4. Опиши, куди підключається плагін, у розділі README «Where your credentials go»: експортер не
   має звертатися до хостів, яких не вибрав користувач.
5. Якщо пристрою потрібні нові об'єкти БД, спершу з'являється міграція в репозиторії дашборду і
   запис у [DB_CONTRACT.md](DB_CONTRACT.md).

Пакети декодерів зараз описують protobuf-повідомлення (`cmdFunc/cmdId`). Плагіну для протоколу
з регістрами (Modbus) потрібен свій тип повідомлення у форматі пакетів, перш ніж його моделі
можна буде виправляти пакетами; доти декодує його вбудований адаптер.

## Збережені облікові дані

Сторінка налаштувань зберігає `{ device: <id плагіна>, ...облікові дані }` у зашифрованому
вигляді (`src/secrets/credentials.ts`). Файли, записані до появи плагінів, не мають поля
`device` і читаються як `ecoflow-mqtt`. Тіло лишається пласким, тож старіша версія
експортера після відкату все ще прочитає файл EcoFlow.
